# PDF 阅读进度 · 笔记 —— 单机应用设计

日期：2026-10-13
状态：已与需求方确认，待实施

## 意图（为什么做）

现有实现是一个单文件网页应用 `deepseek_html_20261013_7c2d5a.html`，双击用浏览器打开，
数据存在 localStorage。它记录 PDF 目录、阅读进度和笔记，但**笔记与 PDF 内容本身是脱节的**——
笔记只挂页码，无法关联到文档里具体划过的那一段。

需求方要的演进方向：

1. 从"双击开网页"变成**真正的单机应用**（有图标、双击即开、数据存本地文件）；
2. 新增**标注 ↔ 笔记**的链路：在 PDF 里划词/画线/框选做标注，笔记直接挂在标注上，
   点笔记能跳回 PDF 原文位置。

"做成单机"本身就是核心动机之一（需求方原话："只是想做成单机"），不带附加条件。

## 目标

- Windows 上双击即可运行的单机应用，不依赖浏览器打开 HTML。
- 保留参考实现的全部既有功能：
  - 本地 PDF 目录扫描与文件树展示
  - 阅读状态（未读/在读/已读等）、页码进度跟踪、跳页、收藏（星标）
  - 统计筛选（chips）、搜索
  - 每份文档的笔记（带页码），Markdown 轻量渲染
  - 导入/导出 JSON
  - 深色/浅色主题（跟随系统）
  - 清理孤儿记录（cleanOrphans）
- 新增标注能力，三种工具：
  - **划词高亮**：选中文字产生高亮
  - **自由画线**：鼠标拖拽画笔迹
  - **矩形框选**：拖出矩形框
- 笔记与标注双向关联：
  - 标注完成后就地弹出小输入框可立即写笔记（可跳过）
  - 事后可在笔记面板补写一条笔记，并手动挑选该文档下的标注挂上去
  - 点击笔记（或其标注徽标）跳转到 PDF 对应页面并定位到标注
- 数据存储从 localStorage 换成本地 SQLite 文件；导出/导入 JSON 保留，作为备份手段。

## 非目标

- 不做云同步、多设备同步、账号体系。
- 不做 AI 自动生成摘要/笔记（笔记内容永远由用户手写）。
- 暂不支持 macOS / Linux（架构上不锁死，见"约束"）。
- 不做 PDF 编辑（增删页面、合并拆分等）——只读 + 标注。
- 不做标注的协作/分享。
- **不做 OCR**：资料为文字版 PDF（需求方确认），扫描件场景不在范围内。
- **不做旧版数据迁移**：需求方确认不需要——localStorage 里的旧数据不导入，新版从头记录（导出/导入 JSON 仅作备份功能保留）。
- 不做安装包与代码签名：只在需求方自己电脑使用，产物为单文件 .exe。

## 反目标（做了就是失败）

- 不能像网页那样"清浏览器缓存数据就没了"——数据必须是独立文件，用户能找到、能备份。
- 不能要求用户装浏览器或手动起服务——双击 .exe 就是全部。
- 不能引入 C 工具链编译依赖（Windows 上装 gcc/llvm 是劝退项）。
- 不为了"新功能"重写既有功能——参考实现已验证的行为尽量原样搬。

## 约束

- **平台**：需求方环境为 Windows（win32）。产物需在 Win10/11 双击可用。
- **参考实现**：`deepseek_html_20261013_7c2d5a.html`（单文件，43KB，无外部依赖），
  UI 与业务逻辑大量可复用。
- **借鉴项目**：[yetone/magpie](https://github.com/yetone/magpie)（MIT，10.6k star）——
  已验证的 Wails v3 + 纯 Go SQLite 的工程实践，其项目结构、打包脚本可参考/抄。
- **许可**：magpie 为 MIT，可借鉴代码；注意保留其许可声明的义务。

## 已定的技术决策（需求方拍板过程记录）

| 功能范围 | 旧功能全保留 + 标注新功能，暂无更多 | 需求方确认"暂时没有了" |

## 方案概述（留给 builder 细化的部分）

整体结构：

```
recorder/
├── main.go                    # Wails v3 入口、窗口、菜单、托盘（如需要）
├── internal/
│   ├── storage/               # SQLite 数据访问层
│   ├── files/                 # 目录扫描、PDF 元信息（页数嗅探）
│   └── export/                # JSON 导入导出（备份用）
├── frontend/                  # 网页界面
│   ├── index.html / app.*     # 由参考实现的 HTML 演进而来
│   ├── pdf.js                 # PDF 渲染（官方发行版打包进资源）
│   └── annotate.*             # 标注层：划词/画线/框选
└── build/                     # 图标、打包配置（参考 magpie）
```

关键设计点（builder 出方案时定，此处仅定方向）：

1. **阅读器基座**：以官方 viewer（vendored 6.4.299，`frontend/vendor/pdfjs/web/viewer.html`）为底二次开发，保留其工具栏、文内查找、
   打印、缩略图、大纲、缩放；标注层作为插件插入其页面画布之上。
2. **进度自动跟踪**：随滚动/翻页自动记录当前页（节流写库，非每滚动像素写一次）；
   页码输入框保留用于跳页，跳页同样更新进度。状态（未读/在读/已读）逻辑沿用参考实现。
3. **标注渲染**：标注层为覆盖在 pdf.js 页面画布上的绝对定位层
   （高亮用 DOM 矩形拼接或 overlay canvas；画线/框选用 SVG 或 canvas）。
   标注数据以"页码 + 页面归一化坐标"存储，缩放/滚动不丢位。
4. **标注 ↔ 笔记关联**：一条笔记可关联 0..n 个标注；一个标注可被 0..n 条笔记引用。
   点击笔记 → 跳页 → 高亮闪烁定位标注。
5. **目录与启动**：SQLite 记录根目录路径；启动时自动重扫根目录、增量比对文件；
   根目录失效时弹窗让用户重新选择。文件身份沿用参考实现的"根目录相对路径"。
6. **SQLite 位置**：应用数据目录（如 `%APPDATA%/recorder/recorder.db`），
   不放程序目录（防 UAC 虚拟化与卸载残留）。导出/备份功能弥补"用户找不到文件"的体验。
8. **打包**：单文件 .exe（Wails build），图标、版本信息齐全；启动时检测 WebView2 运行时，
   缺失时给出明确提示（不做安装包、不做签名——仅需求方本机使用）。
